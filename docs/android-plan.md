# Android plan

Agreed 2026-10-28. Scope: Android **phones**, originally via Google Play; the
Play route was parked the same day (see `docs/android-distribution.md`). Mono repo
(`TimeConverterAndroid/`). The Android phone is remote from the build machine,
so day-to-day QA is the headless emulator here plus screenshots; the phone is
for release candidates.

## Shape (decided)

**Native Kotlin + Jetpack Compose, hand-ported from the Swift core, held to it
by a shared fixture file.** Not Kotlin Multiplatform (would replace the
shipping Swift core with a Kotlin one and put a large dependency on the Apple
side), not Swift-on-Android (immature; a JNI bridge for a 2.5k-line core is
more code than the port). This matches the existing "two thin shells over one
behaviour" rule: three shells now, and behaviour still never differs — it is
pinned by `fixtures/conversion-cases.json`, generated by the Swift core and
asserted by both. `fixtures/readme.md` has the loop.

Port surface, from the Swift core's Foundation use: zone database lookups and
offsets (→ `java.time`), the generic zone name (→ `ZoneId.getDisplayName`),
two hand-rolled formatters (ported verbatim), and `TimeZone.abbreviationDictionary`,
which is Apple-only and needs a small table on Android (`FoundationAbbreviationZoneResolver`
is the one resolver without a direct twin).
